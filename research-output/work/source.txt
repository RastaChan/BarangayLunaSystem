61: ABSTRACT
62: This study developed the Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna, integrating QR-based profiling and SMS notifications to replace inefficient manual administration. Current operations are hampered by slow document processing, physical bottlenecks, and fragmented record-keeping. Utilizing the Rapid Application Development (RAD) model, the researchers engineered a web-based system using PHP, MySQL, and JavaScript to centralize governance tasks. Key features include automated QR code generation for instant resident verification, an online request module for certifications, and an integrated SMS gateway for real-time status updates. Testing and deployment demonstrate that the system minimizes physical visits to the Barangay Hall, eliminates redundant data entry, and provides officials with an administrative dashboard for revenue and service analytics. The implementation of this portal enhances the speed, transparency, and data integrity of local government transactions in Barangay Luna.

INTRODUCTION
120: 
121: 	This chapter presents the project context, purpose and description, objectives and the scope and limitation of the study.
122: Project Context
123: Barangays are the primary government units responsible for issuing essential certifications, including clearances and certificates of residency or indigency. Currently, Barangay Luna relies on manual, paper-based processes, resulting in operational inefficiencies such as long wait times, data redundancy, and misplaced records. The lack of a real-time notification system further necessitates multiple physical visits by residents. To address these challenges, this study proposes the Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna. This web-based platform automates document processing and record management to enhance service delivery, transparency, and administrative organization.
124: Purpose and Description
125: The study aims to digitalize Barangay Luna’s governance by providing a centralized platform for document requests and resident data management. The system enables residents to create digital profiles and apply for various certifications—such as Barangay Clearances and Certificates of Indigency—online. A key feature is the integration of QR-based identification, assigning each resident a unique code for rapid data retrieval and document verification to prevent fraud. For administrators, the system provides a dashboard to manage records, process applications, and monitor service analytics. Automated SMS notifications are integrated to provide residents with real-time updates, reducing physical bottlenecks at the Barangay Hall.
126: Objectives of the Study
127: General Objective
128: To develop a Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna that streamlines document processing, improves data integrity, and enhances service accessibility.
129: Specific Objectives
130: The study specifically aims to:
131: 1. To design a module that can manage resident profiles, staff accounts, barangay services, document templates, complaint records, announcements, and data analytics for revenue and service monitoring.
132: 2. To design and develop a resident management module that generates unique QR codes for secure profiling and identity verification.
133: 3. To design and develop an online document request module that enables digital applications and provides real-time updates via an integrated SMS notification system.
134: 4. To implement a transaction and payment module for recording walk-in payments and maintaining digital financial records.
135: 5. To develop the system using a technical stack comprising HTML, CSS, and JavaScript for the frontend; PHP and for the backend; and MySQL for data management within a Laragon local server environment.
136: Scope and Limitation
137: Scope
138: This study focuses on the development of a Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna designed to improve the efficiency of barangay document processing and resident service management. The system includes the following features:
139: The system maintains a digital database of resident profiles and generates unique QR codes for secure identification.
140: The system provides a web-based portal for the online requesting of various barangay certifications.
141: The system implements QR-scanning functionality for officials to verify document authenticity and retrieve resident data.
142: The system features an administrative dashboard for request processing, account management, and community announcements.
143: The system utilizes an SMS gateway to automate status updates for residents.
144: The system records walk-in payments to ensure financial transparency and transaction tracking.
145: The system enables digital filing of complaint records and the collection of resident feedback.
146: The system provides a data analytics module to monitor revenue and service trends.
147: Limitation
148: The proposed system has the following limitations:
149: The system does not support online payment processing; all fees must be settled via walk-in transactions.
150: The system is focused on administrative document services and does not include emergency response or law enforcement modules.
151: The system is limited to the predefined document types configured within the system settings.

164: REVIEW OF RELATED LITERATURE
165: The Review of Related Literature (RRL) provides a comprehensive overview of existing research and systems relevant to the development of the Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna. This chapter examines local and foreign perspectives on e-governance and digital record management to identify best practices and technological gaps. The literature presented highlights the transition from manual to automated processes, emphasizing the roles of web platforms, QR code identification, and data analytics in enhancing public service delivery.
166: Related Literature
167: In the global landscape of e-governance, Decarli (2024) describes the myCIVIS portal in Italy as a critical interface that bridges national systems with local administrative needs through user-centric design. This necessity for evolution is supported by Andréasson (2023), who explores rural digitalization trends and asserts that grassroots governance must adopt new technologies to ensure continued social development. Furthermore, Qin (2023) provides a theoretical framework on the legal aspects of grassroots governance, highlighting digital transformation as a requirement for sustainable development and social cohesion. In the context of urban administration, Idrus et al. (2022) emphasizes that innovative administrative systems are vital for modernizing population records and village-level services through electronic applications. These concepts are exemplified by Yuwono et al. (2020), who showcases the Banyuwangi model in Asia as a standard for re-engineering government governance to be more efficient and transparent at the grassroots level.
168: In the Philippines, the push for digitalization is supported by national initiatives aimed at streamlining public service delivery. Caotivo (2025) argues that digitalizing frontline services and capacitating digital frontliners are essential priorities for sustainable LGU operations. Albano (2024) supports this by advocating for the use of open-source tools as a cost-effective method for LGUs to build dynamic web-based information systems even in resource-limited settings. The practical implementation of such systems is discussed by Morrison (2023), who highlights the Unified Barangay E-Services System and its use of augmented analytics to monitor service usage patterns. This drive toward accountability is further cited by Daga-ang et al. (2023), who identifies automated profiling as a key step toward achieving the "Seal of Good Local Governance for Barangays." Finally, Sardan et al. (2023) emphasizes that digitizing services through programs like the BEGin initiative in Bacoor City significantly increases public trust and improves accessibility during administrative crises.
169: Related Studies
170: Recent foreign studies demonstrate the practical application of mobile and web technologies in village administration. Suriyani et al. (2024) developed the siPalui application in Indonesia to shift services to electronic formats, noting that while it improved convenience, network stability remains a primary challenge. Similarly, Pertiwi et al. (2024) developed a Village Citizen Reporting Website and found that online platforms significantly enhance the speed of administrative response. Technological integration is further explored by Budiarto et al. (2024), who proved that web-based designs in the Pakuhaji District streamline multi-village interactions. In Surabaya, Ayuningtyas et al. (2022) supported "Smart City" initiatives by centralizing resident data and service requests through a unified website. These studies are complemented by Hanafiah et al. (2021), who demonstrated that utilizing G-Suite with QR codes for administrative services improved accessibility by allowing services to be performed at any time.
171: Local studies have extensively explored barangay management systems tailored to Philippine needs. The Kabataan-Konek (2025) study developed a youth information system integrating QR codes for document verification, achieving high marks for reliability. In Pasig City, Enaño et al. (2025) utilized linear regression algorithms in the BarangayConnect portal for demographic forecasting, which resulted in reduced manual workloads. Evaluation of these tools is provided by Rey et al. (2024), who used the Technology Acceptance Model to confirm that residents perceive web-based e-governance as useful and easy to navigate. Furthermore, Duco et al. (2023) tested a framework for a mobile and web platform in Mandaluyong City, receiving high satisfaction ratings for its digital profiling capabilities. This is supported by Alegado (2023), who found that the Docu-Go system serves as a secure and efficient modern alternative to traditional record-keeping.
172: Related Systems
173: Several existing systems offer benchmarks for the Smart Barangay Citizen Portal, such as WeBarangay in Quezon City, which is noted for its high-speed performance, and BarangayConnect in Pasig City, which automates document requests and community planning. International systems like siPalui in Indonesia provide smartphone-based document services, while the BALANGAY System aids in incident reporting through decision-support heatmaps. Additionally, the One Barangay system serves as a mobile and web-based solution designed for secure data management and service productivity in the City of Manila.
174: Synthesis of the Study
175: The reviewed literature and studies emphasize that digital transformation is essential for improving the efficiency and transparency of local government services. Existing platforms primarily focus on digitizing traditional processes such as record management and document requests to reduce manual workloads. However, while these systems contribute to administrative efficiency, many remain limited to basic automation and lack integrated mechanisms for secure identity verification and real-time notification.
176: The proposed Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna differentiates itself by integrating QR-based resident profiling and an SMS notification system into a single platform. The use of QR codes enables fast and secure identification, prevents duplicate records, and supports document verification through scanning, which improves data integrity. Furthermore, the inclusion of an SMS gateway strengthens communication by providing residents with real-time updates on the status of their requests. Unlike traditional systems that depend on manual follow-ups, this project incorporates a feedback mechanism and a data analytics module for revenue monitoring. These enhancements provide a more secure, transparent, and user-centered solution, contributing to the advancement of smart governance at the local level.

202: Conceptual Framework
203: The conceptual framework of this study follows the Input–Process–Output (IPO) model to define the operational logic of the Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna. This model delineates the flow of data from user entry through technical execution to the generation of administrative outputs. By structuring the system into these three distinct phases, the framework demonstrates how resident data, document requests, and payment details are systematically transformed into secure QR profiles, real-time notifications, and analytical reports.

207: Methodology
208:  The researchers adopted the Rapid Application Development (RAD) methodology to prioritize iterative prototyping and continuous user feedback over traditional, linear development. This methodology is divided into four distinct phases: Requirements Planning, User Design, Construction, and Cutover. By utilizing RAD, the researchers can rapidly develop and refine the system’s core features—such as the QR code generator and SMS module—ensuring the final portal aligns with the operational requirements of Barangay Luna and the accessibility needs of its residents.

269: Process Model and Data Design
270: The Existing Context Diagram delineates the manual administrative workflow of Barangay Luna. Labeled as the Barangay Manual Processing System, the current model involves two primary external entities: the Resident and the Barangay Staff. The resident serves as the data source for physical inputs, including handwritten personal profiles, document applications, and cash payments. Conversely, the Barangay Staff functions as the manual processor, responsible for physical record verification and document issuance. This diagram identifies a significant technological gap, as data at rest is stored in physical logbooks rather than a digital database, leading to systemic inefficiencies in data retrieval, transaction tracking, and resident communication.

283: Existing Data Flow Diagram
284: The Existing Data Flow Diagram provides a functional decomposition of the current manual operations in Barangay Luna. The data flow initiates with the Resident providing "Document Request Data" or "Complaint Details" to the Initial Intake Process. This data is then transmitted to the Verification Phase, where the Barangay Staff manually cross-references the information against existing paper files.
285: Upon validation, the data is written into a Physical Logbook, which acts as the system's primary Data Store. This "Data at Rest" is later retrieved by staff to facilitate the Document Preparation or Resolution Process. The final "Output Data"—in the form of a physical certification or a complaint update—is then released to the Resident. This diagram underscores the systemic vulnerabilities of the current model, specifically the high latency in data retrieval and the risk of data loss inherent in a non-redundant, paper-based storage system.

328: Proposed Data Flow Diagram
329: The revised Proposed Data Flow Diagram (Level 1) illustrates the detailed flow of data within the Smart Barangay Portal with QR Profiling & SMS Alerts For Barangay Luna. The system begins with Process 1.0: Resident Verification, Registration and QR Generation, where residents submit their personal information and valid ID for verification by the barangay staff. Once approved, the system stores the resident record in the Residents Database (D1) and generates a digital QR profile for the resident.
330: In Process 2.0: Document Request Handling, residents submit document requests which are validated using resident data retrieved from D1. The request details are then stored in the Document Request Database (D2). The requests proceed to Process 3.0: Barangay Staff Approval and SMS Notification, where the barangay staff reviews and approves or rejects the requests. The system updates the request status in D2, sends SMS notifications to residents regarding their request status, and stores notification records in the SMS Logs (D3).
331: The system also includes Process 5.0: Feedback Management, where residents submit feedback and ratings that are stored in the Feedback Database (D5). Feedback summaries are then made accessible to the admin for monitoring purposes. In Process 6.0: Payment Processing, barangay staff confirms walk-in payments, and the transaction details are stored in the Payment Records database (D4).
332: Lastly, Process 4.0: Reports and Analytics retrieves resident data, request records, payment data, and feedback data from the databases to generate reports and statistical analytics requested by the admin. The revised diagram provides a clearer and more organized representation of the system by improving data flow directions, separating the responsibilities of the admin and barangay staff, and ensuring compliance with proper Data Flow Diagram standards.
